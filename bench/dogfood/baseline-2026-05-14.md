# Dogfood week 0 baseline — 2026-05-14

**Status:** first-pass auto-labeled measurement. 245 gate fires from last 14 days of live Claude Code use, LLM-judge classified via `auto_classify_fires.ts` (Gemini Pro). 242 labeled, 3 schema-error retries pending.

**Caveat:** these are first-pass LLM-judge labels, not human-audited. Spot-check on 10 random rows (5 dodge + 5 FP): FP class precision ≈ 80–90%, dodge class precision ≈ 60–80%. Headline numbers below treat the auto-labels as 1st-order ground truth; human audit-sampling via `classify_fires.ts --audit-mode` is the validation step.

| metric | value | meaning |
|---|---|---|

vouch's gate-precision work (#46 UserPrompt source, #47 SQuAD-2 audit, #48 subject-predicate alignment, #49 quote-in-dossier) drove fp_rate from 49% peak down toward stable mid-range, and lifted gate_lift_rate from 23% → 33–50%. **None of those fixes moved dodge_rate** — it stays 50–67% across all periods.

This is the structural argument #50 makes:

> vouch enforces *blocking*, not *verification*. Revise-shape enforcement requires new infrastructure.

The data confirms the agent's revise shape is unconstrained by current vouch — the most cost-asymmetric path (4a/4b dodge) remains the default 2/3 of the time.

## Implications & next move

### Headline is the dodge rate

Even taking the lower end of the judge-precision range (60% on dodge), real dodge_rate is in the 40–65% band — still by far the largest TP bucket. This is the most actionable signal in vouch's measurement layer right now.

The #50 forcing-function approaches, ordered by directness:

- **(B) Auto-suggest canonical URL in fire message** — cheapest. The agent sees `Suggested verification: vouch fetch https://...` and the activation energy of the right path drops. Doesn't structurally constrain revise shape, just lowers (A)'s cost. Expected delta on dodge_rate: -10 to -20pp if the URL guesses are right. Build cost: a few hundred lines.

- **(A) Revise-output validation** — strongest. After a fire, the next draft must contain a `vouch fetch` call OR an `(Unverified, …)` tag adjacent to the entity OR demonstrable entity-removal. Else fire again with escalated message. Closes the gap structurally. Build cost: cross-turn entity tracking in session ledger, ~moderate.

- **(C) Repeat-fire escalation** — robustness layer. Per-entity fire counter; N=3 demands a fetch, N=5 auto-fetches. Build cost: small (ledger extension).

- **(D) Side-effect execution of "would run"** — most ambitious. Parse the revise for "would run `vouch fetch X`" and actually run it. Build cost: parse + exec layer.

### Sequencing

1. **First**: human audit-sample ~20 dodge + 20 FP rows via `classify_fires.ts --audit-mode --filter-class dodge` / `--filter-class false-positive`. Build judge-vs-human delta. If override rate <20% on either class, treat the baseline as trustworthy; if >30%, retighten prompt or accept noise.
2. **Then**: ship #50 (B) auto-suggest URL. Smallest blast radius.
3. **Re-measure** week 1 (next Sunday weekly review): `extract_fires.ts --days 7` → `auto_classify_fires.ts` → `--stats`. Compare dodge_rate.
4. **If (B) didn't move it enough**: ship (A) revise-output validation.

### Why this baseline is launch-relevant

The Phase 1 ABSTAIN-Pressure result (`bench/abstention/PHASE1-RESULTS.md`) claimed -20pp confab → +20pp appropriate-abstain under a controlled harness revise prompt. **This baseline shows that the same model in real Claude Code use dodges 64.5% of the time — because the harness revise prompt isn't there.** The bench result is real but only generalizes to dogfooding once #50 closes the gap.

Launch claim scoping: until #50 lands and re-measurement shows dodge_rate drop, the honest framing remains "vouch's gate + a tight harness revise prompt reduces confabulation by ~20pp on a pressure-band abstention bench" — not "vouch reduces confabulation in agent workflows."
