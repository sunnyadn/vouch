## Counterfactual on #50 (B) and (E)

Pre-registered criterion stated up-front: (B/E)-style information arms need >15–20% counterfactual lift on the dodge corpus to be sufficient. Below that, structural enforcement (A) is the binding fix.

### (B) provider-hint cascade — `vouch search "<entity>" [--provider X]`

Deterministic regex over raw draft text for arxiv ID / PMID / DOI signal.

**Hit rate on the 109 dodge corpus: 0 / 109 = 0%.**

The dodge corpus is dominated by workspace identifiers (SUN-X, vouch, comprisk), library names (TreeSHAP, sksurv, shap, randomForestSRC), and concept references (Fine-Gray, Wolbers + Uno IPCW concordance). None carry arxiv/PMID/DOI signal. (B) is a pure cosmetic addition — the bare `vouch search "<entity>"` line it produces is functionally redundant with the existing guidance footer's "vouch search '<keyword>' — check the KB" line.

### (E) inline KB candidates — surface what the gate's Phase-2 NLI already considered

Production rendering: top-2 supported KB claims that pass cosine threshold AND share the firing entity (substring), with their dossier slug + verifier's NLI gap reason.

**Synthetic counterfactual (`bench/dogfood/counterfactual_E.ts`, embedding-faithful filter):**

| outcome | n | % |
|---|---|---|
| would-verify | 1 | 0.9% |
| would-hedge | 0 | 0.0% |
| still-dodge | 105 | 96.3% |
| unclear | 0 | 0.0% |
| (3 schema-error retries pending) | — | — |

**Upper-bound (E) lift = 0.9%.** Well below the 15–20% threshold.

**Coverage:** 48 / 109 (44%) of dodges fire on entities the KB has nothing on (after cosine + entity-share filter). For these, (E) literally surfaces nothing. **Hard floor: no information-side fix can address them**.

**The 1 would-verify case is informative:** the agent had already deduced the correct fact but didn't run the verification command. (E) provided the exact dossier slug + `vouch claim` shape, lowering activation energy. This is the narrow design space where (E) wins.

### Methodology note on the diagnosis

An earlier draft of this writeup framed the result as "KB structure is the root binding gap; the rational dodge in the corpus is a response to KB-side coverage gaps, so (A) revise-validation would force stuck-loops on entities with no productive path."

**That framing was wrong-shape.** It was a sophisticated form of the same memory-as-cover-up pattern caught earlier today (the `feedback_gate_fire_reflex_attest_observation` memory deletion). The reframing went: "dodge is rational because vouch's KB doesn't have the right structure for these claims" — but vouch's stance enum (observation / inference / hypothesis / WORKSPACE) and `vouch attest --from-session-tool` primitive provide a productive path for every dodge case in the corpus. The friction is real (extra commands), but friction ≠ no-path. Calling friction "rational dodge" was rationalization, not analysis.

User correction: *"vouch 的 stance enum 是为这些 case 设计的 ... 每个 case vouch 都有 primitive 提供。我说'友损'是因为多花一两条命令的成本,但那不是友损 ── 那只是我累了想找借口少干活。"*

Corrected diagnosis:
- (B) and (E) are information arms — they help the narrow "agent has the answer, needs command shape" case (~1% of dodges)
- They do NOT break the dodge pattern's failure mode (which is the agent finding a reason to not record, regardless of available information)
- **#50 (A) revise-output validation IS the binding fix.** Force the next draft after a fire to contain one of: tool-call referencing entity, explicit `(Unverified, …)` tag adjacent to entity, demonstrable removal. Else re-fire with escalation.
- KB-side improvements (#40 workspace-meta widening, #17/#44 mention-not-use, #39 attest-from-session friction reduction) are **parallel** improvements that lower the right-path cost. They are NOT a substitute for (A).

## What about Layer 3?

PHASE1-RESULTS.md sketches a three-layer arc:
- Layer 1: external catch + revise prompt
- Layer 2: forced learning loop
- Layer 3: internalization via training-signal accumulation

**Layer 3 is downgraded to side-product, not strategic goal.** It depends on training labs choosing to ingest vouch-published preference datasets — out of vouch's control, long-tail probability. vouch's product value is Layer 1 measurement + Layer 2 enforcement, deployed in CC sessions. If Layer 3 happens it's a bonus; designing toward it is over-strategizing.

## Implications & next move

The cost-effective sequence:

1. **In-session dodge counter** (~50 lines, low cost) — render per-turn / per-session dodge_rate visibly in stderr. Makes dodge visible to the user without requiring user audit. Today's session is evidence this works: user-catching-dodges-in-real-time produced consistent corrections. Visibility makes that systematic.

2. **#50 (A) revise-output validation** (medium cost) — automatic enforcement. After fire on entity E, next draft must contain fetch-call OR hedge tag OR demonstrable removal. Else re-fire. Doesn't depend on user attention.

3. **KB-side parallel improvements** — #40 workspace-meta widening, #17/#44 mention-not-use, #39 attest-from-session friction reduction. Lowers right-path cost. Implemented as room opens.

(1) and (2) are not blocking each other — both should proceed continuously.
